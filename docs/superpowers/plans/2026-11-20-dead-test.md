# 0.15: the dead test: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The cartridge starts in diag mode into a dead test that needs no
RAM, tests and reports everything it can on every channel (text, colour,
bit boxes, beeps, speech), and on a pass rolls on into the unchanged suite;
also a standalone 8K dead test; as version 0.15, local.

**Architecture:** The dead test is a set of 8K cartridge banks after the
suite's (bank 5 on). Every other bank's tail carries the diag header and a
two-instruction stub into bank 5. Bank 5 runs the no-RAM RAM test (stage
B) and leaves its results in non-RAM storage (PIA direction registers, the
stack pointer, PIA control bits); later banks are entered through the
tail's XBANK with a phase number in Y: stage A (OS ROM CRCs, with any good
RAM page), the other chips, the show bank (text rows chosen by rewriting
ANTIC's display-list pointer, bit boxes, beeps, keys) and the speech banks.
The hand-over keeps a dead bank (ordinary header) in and jumps through the
reset vector, so the OS cold-starts the suite as today.

**Tech Stack:** 6502 assembly (MADS), Python 3 tools (build.py, mkcar.py,
sim.py on py65, carttest.py, new deadtest.py, mkfont.py, mkdtext.py,
mkcrc8.py, mkwords.py), espeak-ng (once, for the words).

**Spec:** `docs/superpowers/specs/2026-11-20-dead-test-design.md`

## Global Constraints

- Version `0.15` (build.py `VERSION`). Release files:
  `carts/diag-cart-8mbit-v0.15.bin`, `carts/diag-cart-v0.15.car`,
  `carts/diag-deadtest-v0.15.car` (CAR type 1, standard 8K),
  `carts/diag-deadtest-v0.15.rom` (raw 8192 bytes, for an EPROM).
- Bank map (8 Mbit and 128K): suite banks 0-4 unchanged; `DEADBK = 5`
  start + stage B; 6 show; 7 stage A; 8 the other chips; 9 on the words
  (8 Mbit only; the 128K has no speech). Standalone (`STANDALONE`): one
  bank: start, stage B, a reduced show, no stage A, chips or speech; the
  build fails if it passes 7936 bytes.
- Every dead bank: `$A000 jmp` cold start, `$A003 jmp` phase entry (Y =
  phase id), `$A006 rts` (the dead banks' init address); code and data
  below `$BF00` (the code-bank CRC32 at `$BFF6` covers `$A000-$BEFF`).
  A bank that shows ROM text carries the font, chars 0-63 in Atari's
  internal order, at `$A400-$A5FF` (1K-aligned CHBASE `$A4`).
- The tail, every bank of both AtariMax images (bytes at `$BFE0`):

  | at | bytes | |
  |---|---|---|
  | $BFE0 | `A2 00 9D 00 D5 4C 00 A0` | run: bank 0's cold start (as now) |
  | $BFE8 | `8D 05 D5` | `sta $D500+DEADBK` (diag init: to bank 5) |
  | $BFEB | `4C 00 A0` | `jmp $A000` (runs in bank 5) |
  | $BFEE | sum lo, hi | the bank's sum (as now) |
  | $BFF0 | `9D 00 D5 4C 03 A0` | XBANK (as now) |
  | $BFF6 | CRC32 | code banks and dead banks (as now) |
  | $BFFA | `E0 BF 00` | run address, cartridge in |
  | $BFFD | `80 E8 BF` | suite and blank banks: diag, init $BFE8 |
  | $BFFD | `04 06 A0` | dead banks: ordinary, init $A006 (rts) |

  Standalone: `$BFFA` = `00 A0`, `$BFFC 00`, `$BFFD 80`, `$BFFE 00 A0`;
  no `$D5xx` write anywhere in it.
- Stage B (between labels `SBBEG` and `SBEND` in bank 5): no JSR, RTS,
  PHA, PLA, PHP, PLP, RTI, BRK; no zero-page or indirect addressing; no
  read of `$C000-$FFFF` except `$D000-$D7FF`; RAM touched only by the
  unrolled test instructions. First instructions: `SEI`, `NMIEN` = 0.
- **The results interface** (set by stage B, kept until the hand-over;
  read DDRA/DDRB with PACTL/PBCTL bit 2 = 0, after ORA/ORB = `$FF`):
  DDRA = bank 1's bad bits (`$0000-$3FFF`), DDRB = bank 2's
  (`$4000-$7FFF`), S = bank 3's (`$8000-$9FFF`); PACTL bit 0 = 1: zero
  page bad; PBCTL bit 0 = 1: stack page bad; a mask of `$FF` = no RAM.
  **The good page:** the first bank whose mask is 0 gives the RAM stage A
  and the show bank use: bank 1 `$0400-$0BFF`, bank 2 `$4000-$47FF`,
  bank 3 `$8000-$87FF`; none = no-RAM mode.
- Text, exactly (40-column rows, mode 2):
  - row 0, inverse: ` DEAD TEST` and the version at the right, as the
    suite's title bar (`V0.15`)
  - `ZERO PAGE  OK` / `ZERO PAGE  BAD`; `STACK      OK` / `STACK      BAD`
  - `BANK 1 $0000-$3FFF  OK` / `BAD` / `NO RAM` (bank 2 `$4000-$7FFF`,
    bank 3 `$8000-$9FFF`), with `76543210` at columns 30-37 when OK or
    BAD; a quad-width player under those digits marks the bad bits
  - `DEAD TEST -- PASS` / `DEAD TEST -- FAULT`
  - `START=GO ON  SELECT=TONES  OPTION=FLASH`
- Colours: border = verdict (`C_GREEN $C8` pass, `C_RED $34` fault); a
  bank row's background (COLPF2): green OK, red BAD, `C_NONE = $04` NO
  RAM (red for bank 1); text luminance `C_TEXTLUM $0C`; bit boxes red.
- Beeps: report.asm's tones (`tt_frq`, `tt_len` entries T_DM1-T_DM3,
  T_ALONG, T_BSHORT, T_J1-T_J4, copied, not shared): fault = doom, then
  long beeps = bank (1-3; zero page and stack are bank 1), short beeps =
  bit + 1 (D0 = 1), the lowest bad bit, as the suite; pass = the charge.
- Keys, as the suite: START or fire = go on (the hand-over); SELECT or
  down = tones (and words) again; OPTION or up = full-screen flash. A
  press counts after a release (edge). A fault waits forever; a pass
  shows `DEAD TEST -- PASS` with the charge, then hands over by itself.
- No OS ROM image in git: CRC tables are committed as numbers.
- Builds while working: `python tools/build.py --nodeploy`; the last build
  deploys to `_diag`. Commit locally after each task (noreply author,
  attribution lines); never push. Never run test 7 in the simulator.
- The suite's behaviour after the hand-over is unchanged; existing checks
  may need their times moved by the dead test's seconds, never their
  expected texts.

5. **A good machine:** dead test, then the suite exactly as in 0.14; the
   existing cartridge checks pass. Tests `show-pass` (Task 4) and the
   regression runs in Task 9.

### Task 3: Stage B, the RAM test with no RAM

**Files:**
- Create: `src/deadtest/stageb.asm` (bank 5, between `SBBEG` and `SBEND`)
- Modify: `src/deadtest/main.asm`, `tools/sim.py`, `tools/deadtest.py`

**Interfaces:**
- Produces: the results interface (Global Constraints), then phase entry
  of the next bank (Y = phase id).
- Produces (sim): PIA DDRA (`$D300` with PACTL bit 2 = 0, as DDRB);
  `--hole LO-HI` (reads float, writes lost); at the end the line
  `dead: ddra=$xx ddrb=$xx s=$xx pactl=$xx pbctl=$xx` (the values when the
  run stops or at the hand-over, whichever is first).

The patterns (decided): per bank, two passes; pass 0 writes byte X of
page P with `X EOR P`, pass 1 with `X EOR P EOR $FF`; after a pass has
written every page of the bank, each byte is read back and
`read EOR expected` is ORed into the bank's mask; zero page and the stack
page also set their flag bits. Order: bank 3 into DDRA, moved to S, then
bank 2 into DDRB, then bank 1 into DDRA (cleared first). One X loop per
pass, its body unrolled across the bank's pages (MADS `.rept`).
