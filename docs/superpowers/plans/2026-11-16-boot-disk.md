# Boot disk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `disks/diag-disk-v0.9.atr`: a single-density boot disk that runs the whole suite as the cartridge does, from 8K up, by chaining pieces from disk.

**Architecture:** The cartridge's structure with disk loads for bank switches. Every piece is a tape-style image (6-byte header, entry at LOAD+6) at $0900 with the shared results page (BSS) at $0800; a small loader, carried by every piece, copies itself to $0700 and reads the next piece with the OS's `SIOV`. The system pieces are `system/main.asm` built with `DISK` (as the cartridge banks are built with `ROM`); the two RAM pieces are tape 1 built with `DISK`.

**Tech Stack:** MADS 6502 assembly, Python 3 tools (build.py, new mkatr.py), the py65 simulator (tools/sim.py).

**Spec:** `Atari-diag-boot-disk-scope.md`

## Global Constraints

- Version 0.9; release file `disks/diag-disk-v0.9.atr`; title bar ` DIAG-DISK `; the ROM test's self-check line `DIAG DISK`.
- ATR: single density, 720 sectors × 128 bytes, 16-byte header (magic $0296, size in 16-byte paragraphs, sector size 128).
- Boot: sectors 1-2 at $0600 (header flags 0, count 2, load $0600, init → an `rts`); the OS calls $0606.
- Results page (BSS) $0800 for every piece; pieces load at $0900; a piece that must run on 8K ends by $1BFF; the screen is at $1C00 or above.
- The chain loader runs at $0700 and must end before $07FE ($07FE/$07FF: the "back from the long test" mark, $5A/$A5).
- Entries: LOAD+6 (power-on for RAM pieces, warm for the others), LOAD+9 (RAM pieces: the RAM test again from the menu).
- Piece numbers: 0 RAM8, 1 RAM16, 2 MENU, 3 ROM, 4 INPUT, 5 PORTS, 6 SOUND, 7 VIDEO, 8 HELLO (data, at $1C00), 9 MEM.
- XREQ: 0 the menu, 1-7 that test, 8 the long test, 9 the results, $80 the power-on hand-over from a RAM piece.
- Each format carries only the code it can run; no timers except the RAM summary's three-code auto-continue; every action keeps a console key, a keyboard key and the joystick.
- Commits local only (noreply author), ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Build with `--nodeploy` until the last task.

## Review Focus

- A disk read failure (door open, bad sector): red border, tone, `DISK ERROR` on row 23, a press retries. Tested in Task 1 with `--diskerr`.
- An 8K 400: the boot must pick RAM8, and the screen must not sit where a later piece loads. Tested in Task 4.
- The VBI vector left pointing into overwritten code (the long test sets VVBLKI): the loader restores VVBLKI/VVBLKD before interrupts go on. Tested in Task 5 (back from the long test).
- A held or stuck control at a piece's entry must not act (fire held from the previous screen). Covered by `waitrel`/`joyc` priming at each entry; checked in Task 3's menu walk.
- No picture (DISPOK 0): all tests in order across pieces with no menu. Tested in Task 3.
